Webhooks

The panel pushes signed events to URLs you register. Use this to react to domain.created, ssl.issued, deploy.completed, mailbox events, and more — without polling.

Overview #

Each webhook endpoint is created via Developer ▸ Webhooks (or its API equivalent). On creation you receive a unique signing secret, returned exactly once. Every delivery to your URL carries an HMAC-SHA256 signature computed with that secret over the raw request body — verify before acting.

Important. The delivery handler considers any 2xx response success. Anything else is a failure → retried with exponential backoff (see below). Reply quickly (under ~5 seconds) — the panel times out long-running receivers.

Delivery headers #

HeaderPurpose
Content-Typeapplication/json
X-Betazen-EventEvent key, e.g. domain.created. Match against the catalog below.
X-Betazen-DeliveryUnique delivery id. Use this for idempotency on your side — the panel may retry the same delivery.
X-Betazen-TimestampUnix-seconds. Reject deliveries older than ~5 minutes (replay protection).
X-Betazen-Signaturesha256=<hex hmac>. The HMAC is over the raw request body bytes, keyed with the endpoint's signing secret.
User-AgentBetazen-Webhook/<version>

{

Top-level shape is identical for every event. The data object's contents differ per event — see the catalog for what each one carries.

Signature verification #

Compute HMAC-SHA256(signing_secret, raw_body), hex-encode, prefix with sha256=, and constant-time-compare against X-Betazen-Signature. Use the raw request bytes — re-serialising via your JSON parser will mismatch (key ordering, whitespace).

// Node.js + Express. Mount BEFORE express.json() so we get the raw body.
import crypto from "node:crypto";
import express from "express";

const app = express();
const SECRET = process.env.BZ_WEBHOOK_SECRET;

function rawBodyMiddleware(req, _res, next) {
  let buf = [];
  req.on("data", (c) => buf.push(c));
  req.on("end", () => { req.rawBody = Buffer.concat(buf); next(); });
}

app.post("/betazen", rawBodyMiddleware, (req, res) => {
  const sig    = req.header("x-betazen-signature") || "";
  const ts     = parseInt(req.header("x-betazen-timestamp") || "0", 10);
  const expect = "sha256=" +
    crypto.createHmac("sha256", SECRET).update(req.rawBody).digest("hex");

  // 1. Replay protection — reject anything older than 5 minutes.
  if (Math.abs(Date.now() / 1000 - ts) > 300) return res.status(401).end();
  // 2. Constant-time compare.
  const a = Buffer.from(sig);
  const b = Buffer.from(expect);
  if (a.length !== b.length || !crypto.timingSafeEqual(a, b)) {
    return res.status(401).end();
  }

  const evt = JSON.parse(req.rawBody.toString("utf8"));
  console.log("verified:", evt.event, evt.delivery);
  res.status(200).end();
});

app.listen(3000);
# Python + Flask. request.get_data(cache=True) returns raw bytes.
import hmac, hashlib, time, os
from flask import Flask, request, abort

app = Flask(__name__)
SECRET = os.environ["BZ_WEBHOOK_SECRET"].encode()

@app.post("/betazen")
def betazen():
    sig = request.headers.get("X-Betazen-Signature", "")
    ts  = int(request.headers.get("X-Betazen-Timestamp", "0"))
    body = request.get_data(cache=True)  # raw bytes — do NOT use .json

    # 1. Replay protection.
    if abs(time.time() - ts) > 300:
        abort(401)
    # 2. Constant-time compare.
    expect = "sha256=" + hmac.new(SECRET, body, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(sig, expect):
        abort(401)

    import json
    evt = json.loads(body)
    print("verified:", evt["event"], evt["delivery"])
    return "", 200
// Go + net/http. Read body once, then re-parse.
package main

import (
    "crypto/hmac"
    "crypto/sha256"
    "encoding/hex"
    "encoding/json"
    "io"
    "net/http"
    "os"
    "strconv"
    "time"
)

var secret = []byte(os.Getenv("BZ_WEBHOOK_SECRET"))

func verify(w http.ResponseWriter, r *http.Request) {
    body, err := io.ReadAll(r.Body)
    if err != nil { http.Error(w, "bad body", 400); return }

    ts, _ := strconv.ParseInt(r.Header.Get("X-Betazen-Timestamp"), 10, 64)
    if abs(time.Now().Unix()-ts) > 300 {
        http.Error(w, "stale", 401); return
    }

    mac := hmac.New(sha256.New, secret)
    mac.Write(body)
    expect := "sha256=" + hex.EncodeToString(mac.Sum(nil))
    sig := r.Header.Get("X-Betazen-Signature")
    if !hmac.Equal([]byte(sig), []byte(expect)) {
        http.Error(w, "bad sig", 401); return
    }

    var evt struct {
        Event    string `json:"event"`
        Delivery string `json:"delivery"`
    }
    json.Unmarshal(body, &evt)
    println("verified:", evt.Event, evt.Delivery)
    w.WriteHeader(200)
}

func abs(x int64) int64 { if x < 0 { return -x }; return x }

func main() {
    http.HandleFunc("/betazen", verify)
    http.ListenAndServe(":3000", nil)
}

Retries & backoff #

Any non-2xx response (or a connection error / timeout) is a failure. The delivery is re-queued with exponential backoff:

AttemptDelay
1immediate
2+30 seconds
3+2 minutes
4+10 minutes
5 (final)+1 hour

After the 5th failed attempt the delivery is marked dead and surfaces on the Webhooks page's Recent deliveries tab with the last response body excerpt.

Use the delivery id for idempotency. A receiver that 200s but then crashes before persisting will get the same delivery id again on retry — store the id and skip if you've seen it.

Test fire #

From the Webhooks page (or via POST /api/v1/whm/developer/webhooks/<id>/test) you can synchronously dispatch a webhook.test event. The response carries the receiver's HTTP status and the delivery id, so you can verify your endpoint in real time without waiting for a real event to fire.

Inbound — GitHub auto-deploy #

Each Deploy Software project has its own inbound webhook URL + secret, configured directly on GitHub. The panel verifies X-Hub-Signature-256 using the per-project webhook_secret (visible in the project's Edit modal), then triggers a deploy of every service whose git_branch matches the push ref.

Configure on GitHub

  1. Open the repo on GitHub → Settings → Webhooks → Add webhook.
  2. Payload URL: https://<your-panel>/api/v1/deploy/webhooks/project/<project_id>
  3. Content type: application/json
  4. Secret: the webhook_secret from the project's Edit modal in the panel.
  5. Events: pick Just the push event.

The handler returns 200 even on signature failure — deliberately indistinguishable from a deleted endpoint. Failed deliveries (and successful ones) surface on the project page's Last webhook timeline so the operator can confirm GitHub is reaching the panel.
